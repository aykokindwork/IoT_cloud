# IoT Intrusion Detection System: Cloud Analytical PlatformIoT Intrusion Detection System: Cloud Analytical Platform

Программный комплекс облачного уровня для гибридной системы обнаружения вторжений (IDS) в инфраструктурах Интернета вещей. Обеспечивает глубокий анализ сетевого трафика с применением нейронных сетей и централизованное хранение инцидентов информационной безопасности.

# Архитектура системы

Система реализует гибридную модель обработки данных Edge-Cloud:

    Edge Layer (Go): Первичный захват трафика, экстракция признаков и низкоуровневая фильтрация.

    Transport Layer (Apache Kafka): Асинхронная передача векторов признаков из «серой зоны» для углубленного анализа.

    Cloud Layer (Python/FastAPI): Мультиклассовая классификация угроз и персистентное хранение результатов.

Технологический стек

    Runtime: Python 3.12, FastAPI (ASGI)

    Machine Learning: TensorFlow 2.16, Scikit-learn, Joblib

    Message Broker: Apache Kafka (Confluent Platform)

    Database: MongoDB 7.0 (NoSQL)

    Infrastructure: Docker, Docker Compose

    Interface: gRPC (Edge level), Async Kafka Consumer (Cloud level)

# Спецификация ML-модели

Аналитическое ядро базируется на нейронной сети прямого распространения (Feed-Forward Neural Network), оптимизированной для инференса на наборе данных CICIoT2023.

    Входные данные: Вектор из 46 статистических признаков сетевого потока.

    Выходные данные: Мультиклассовая классификация по 34 категориям (DDoS, Reconnaissance, Brute-force, Mirai, Benign и др.).

    Препроцессинг: Масштабирование признаков через StandardScaler с сохранением параметров обучения для предотвращения смещения данных (data drift).

# Протокол взаимодействия (Kafka JSON)

Сервис обрабатывает сообщения в топике suspicious-flows. Структура сообщения должна строго соответствовать формату:

    {
      "flow_duration": 12.5,
      "Header_Length": 64,
      "Protocol Type": 6,
      "Rate": 15.2,
      ... [46 признаков]
    }

# Стратегия безопасности

Реализована концепция Zero Trust (ZTA). Каждое событие, не получившее однозначной классификации на граничном уровне, подвергается детерминированной проверке в облачном сегменте. Результаты классификации сохраняются в MongoDB с метками времени и весами уверенности модели для последующего криминалистического анализа и формирования правил для сетевых экранов (Firewall).
